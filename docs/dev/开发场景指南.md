## 一、如何添加新的文档解析器

### 场景

需要支持新的文件格式（如 `.epub`）或替换现有解析引擎。

### 步骤

#### 1. 注册解析器类型

在 `common/constants.py` 的 `ParserType` 枚举中添加新类型：

```python
class ParserType(StrEnum):
    # ... 现有类型
    EPUB = "epub"  # 新增
```

#### 2. 创建解析器

在 `deepdoc/parser/` 下创建新文件 `epub_parser.py`：

```python
class EpubParser:
    def __init__(self, parser_config=None):
        self.parser_config = parser_config or {}

    def __call__(self, filepath, binary=None, callback=None, **kwargs):
        # 1. 读取文件内容
        # 2. 解析为文本块
        # 3. 返回 sections 列表
        sections = []
        # ... 解析逻辑
        return sections
```

#### 3. 注册解析器映射

在 `rag/flow/parser/parser.py` 中添加 ParserType → Parser 类的映射。

#### 4. 注册到租户可用解析器列表

更新数据库初始化数据（`api/db/init_data.py`），将新 `parser_id` 加入默认 `parser_ids`。

## 二、如何添加新的 Agent 组件

### 场景

需要新的工作流节点类型（如"发送 HTTP 请求"、"调用内部 API"等）。

### 步骤

#### 1. 创建组件文件

在 `agent/component/` 下创建 `http_request.py`：

```python
from agent.component.base import ComponentBase, ComponentParamBase

class HTTPRequestParam(ComponentParamBase):
    def __init__(self):
        super().__init__()
        self.inputs = {"url": "", "method": "GET", "headers": {}, "body": ""}
        self.outputs = {"response": "", "status_code": 0}

    def check(self):
        if not self.inputs.get("url"):
            raise ValueError("url is required")

class HTTPRequest(ComponentBase):
    component_name = "HTTPRequest"

    def _invoke(self, **kwargs):
        url = self.get_input("url")
        method = self.get_input("method")
        # ... HTTP 请求逻辑
        self.set_output("response", response_text)
        self.set_output("status_code", status_code)
```

**关键规则**：
- 必须定义两个类：`XxxParam(ComponentParamBase)` 和 `Xxx(ComponentBase)`
- `ComponentBase` 子类名会自动成为 `component_name`（除非显式设置）
- 文件不要以 `base` 开头

#### 2. 自动发现

`agent/component/__init__.py` 的 `_import_submodules()` 会**自动扫描**目录下所有 `.py` 文件（排除 `__` 和 `base` 开头），无需手动注册。

#### 3. 组件生命周期

```
参数构造 → check() 校验 → _invoke() 执行 → set_output() 传递结果
                                        ↓ 异常时
                              max_retries 重试 → exception_method 处理
```

#### 4. 在 Canvas DSL 中使用

```json
{
  "components": {
    "http_0": {
      "obj": {
        "component_name": "HTTPRequest",
        "params": {
          "inputs": {"url": "https://api.example.com", "method": "POST"},
          "outputs": {"response": "", "status_code": 0}
        }
      },
      "downstream": ["llm_0"],
      "upstream": ["begin"]
    }
  }
}
```

class MyToolParam(ComponentParamBase):

class MyTool(ComponentBase):
    component_name = "MyTool"

## 五、如何添加新的 LLM 厂商

### 场景

需要接入新的 LLM 服务商（如 Anthropic、AWS Bedrock）。

### 步骤

#### 1. 添加模型定义

在 `rag/llm/chat_model.py` 中添加新的 `ChatModel` 子类，实现 `_chat` 方法：

```python
class AnthropicChat(ChatModel):
    def _chat(self, messages, **kwargs):
        # 调用 Anthropic API
        response = anthropic_client.messages.create(
            model=self.model_name,
            messages=messages,
            **kwargs
        )
        return response.content[0].text
```

#### 2. 注册工厂和模型

在初始化数据中注册工厂和模型信息。

#### 3. 用户配置

用户在前端 LLM 管理页添加 API Key 即可使用。

## 六、组件重试和异常处理

所有 Agent 组件继承以下异常处理机制：

| 参数 | 默认值 | 说明 |
|---|---|---|
| `max_retries` | 0 | 失败重试次数 |
| `delay_after_error` | 2.0 | 重试前等待（秒） |
| `exception_method` | None | 异常处理方式 |
| `exception_default_value` | None | 异常时的默认输出 |
| `exception_goto` | None | 异常时跳转到的组件 ID |
