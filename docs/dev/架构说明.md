# 架构说明 (Architecture)

> 本文档描述 RAGFlow 0.23.1 的完整工作链路、模块职责、部署方式和进程架构。

---

## 一、进程架构

RAGFlow 后端由 **两种进程** 组成（由 `docker/launch_backend_service.sh` 统一启动）：

```
docker/launch_backend_service.sh
    │
    ├─ ragflow_server.py  (1 个)   ← Quart HTTP API 服务器
    │
    └─ task_executor.py  (WS 个)   ← 文档处理 Worker（默认 2 个）
```

两者通过 **Redis** 通信（任务队列、分布式锁、会话缓存、文档解析进度推送），共享 **MySQL/PostgreSQL** 数据库。

### 1.1 API 服务器 (`api/ragflow_server.py`)

- Quart 框架启动 HTTP 服务
- 自动注册 `api/apps/*_app.py` 中的所有 Blueprint
- 启动时完成：数据库初始化 → 超级用户创建 → Nacos 服务注册（可选）→ 启动定时进度更新线程
- DEBUG 模式下可启用 debugpy 远程调试（环境变量 `RAGFLOW_DEBUGPY_LISTEN`）

### 1.2 任务执行器 (`rag/svr/task_executor.py`)

- 每个 Worker 从数据库轮询待处理任务
- 负责执行文档解析 Pipeline（解析 → 分块 → 向量化 → 索引）
- 支持任务取消检测（`has_canceled`）
- 包含 GraphRAG 知识图谱构建、RAPTOR 分层摘要等子任务

## 二、依赖服务

```
┌─────────────┐   ┌──────────────┐   ┌─────────────┐
│ MySQL /      │   │ Redis        │   │ MinIO        │
│ PostgreSQL   │   │ (队列/缓存    │   │ (对象存储)    │
│ (业务数据)    │   │  /会话/锁)    │   │              │
└─────────────┘   └──────────────┘   └─────────────┘

┌─────────────────────────────┐
│ Elasticsearch / Infinity    │
│ (全文检索 + 向量检索)         │
└─────────────────────────────┘
```

| 服务 | 用途 |
|---|---|
| MySQL / PostgreSQL | 业务数据存储（用户、知识库、文档、对话等） |
| Elasticsearch / Infinity | 全文检索 + 向量检索（chunk 存储和召回） |
| Redis | 任务队列、分布式锁、Session 存储、文档解析进度 |
| MinIO | 文件对象存储（上传文件、解析产物、图片等） |

```
用户上传文件
    │
    ▼

               ▼
┌─────────────────────────────────────────────┐
│ 3. 文档解析 (task_executor.py)                │

│    │                                          │

│    ┌─ deepdoc/parser/excel_parser.py         │
│    ┌─ deepdoc/parser/ppt_parser.py           │

               │
               ▼
┌─────────────────────────────────────────────┐
│ 4. Pipeline 处理 (rag/flow/pipeline.py)       │
│    Pipeline 继承自 agent/canvas.py:Graph      │
│    通过 JSON DSL 定义的组件图处理文档:          │
│                                              │
│    ┌─ Parser 组件: 提取文档原始内容             │

               ▼
```

## 四、Agent 系统 (Canvas) 架构

RAGFlow 的 Agent 采用 **JSON DSL 驱动的有向图** 模式：

```
Canvas DSL (JSON)
    │
    ▼
┌──────────────────────────────┐
│ agent/canvas.py:Graph        │
│ 解析 DSL → 构建组件图         │
│ 拓扑排序 → 按序执行组件        │
└──────────────┬───────────────┘
               │
    ┌──────────┼──────────┐
    ▼          ▼          ▼
┌───────┐ ┌───────┐ ┌───────┐
│ Begin │→│  LLM  │→│  ...  │
└───────┘ └───────┘ └───────┘
    每个组件 = ComponentParamBase + ComponentBase
```

### 组件类型

| 类别 | 位置 | 说明 |
|---|---|---|
| 流程控制 | `agent/component/` | Begin, Switch, Categorize, Loop, Iteration, ExitLoop |
| LLM | `agent/component/llm.py` | 大模型调用（含消息历史窗口、重试、异常处理） |
| 检索 | `agent/tools/retrieval.py` | 知识库检索 |
| 外部工具 | `agent/tools/` | Tavily, Wikipedia, DuckDuckGo, GitHub, Email, SQL, 代码执行器等 |
| 数据处理 | `agent/component/` | VariableAssigner, VariableAggregator, StringTransform, ListOperations |

### 关键设计

- **ComponentParamBase**: 定义参数 Schema（`inputs`, `outputs`, `max_retries`, `exception_method` 等）
- **ComponentBase**: 实现 `_invoke` / `_invoke_async`，组件运行时通过 `set_output` 传递数据
- **LLMBundle**: 组件中访问 LLM 的统一入口，自动解析租户配置的模型工厂和 API Key
- 组件注册通过 `@component_class` 装饰器完成

## 五、GraphRAG 和 RAPTOR

### GraphRAG (`graphrag/`)

两种模式：

| 模式 | 位置 | 说明 |
|---|---|---|
| General | `graphrag/general/` | 完整知识图谱：实体提取 → 社区检测(Leiden) → 社区报告 → 思维导图 |
| Light | `graphrag/light/` | 轻量图谱提取 |

入口函数：`graphrag/general/index.py::run_graphrag_for_kb`，在 `task_executor.py` 中被调用。

### RAPTOR (`rag/raptor.py`)

分层摘要技术：对 chunk 进行聚类 → 逐层生成摘要 → 构建树状索引，支持跨文档的长范围问答。

## 八、部署方式

### 8.1 Docker 部署（生产推荐）

```bash
cd docker
docker compose -f docker-compose.yml up -d
```

包含所有依赖服务（MySQL, ES, Redis, MinIO）和应用服务。

### 8.2 源码开发

```bash
# 启动依赖服务
docker compose -f docker/docker-compose-base.yml up -d

# 启动后端（API Server + Task Executor）
source .venv/bin/activate
export PYTHONPATH=$(pwd)
bash docker/launch_backend_service.sh

# 启动前端
cd web && npm run dev
```

### 8.3 环境变量（关键）

| 变量 | 说明 |
|---|---|
| `DATABASE_TYPE` | 数据库类型：mysql / postgres |
| `DOC_ENGINE` | 检索引擎：elasticsearch / infinity |
| `MINERU_APISERVER` | MinerU API 地址 |
| `WS` | Task Executor 进程数（默认 2） |
| `QUART_RESPONSE_TIMEOUT` | Quart 响应超时（默认 600s） |
| `HF_ENDPOINT` | HuggingFace 镜像站 |
| `RAGFLOW_DEBUGPY_LISTEN` | Debugpy 远程调试端口 |

## 九、线程安全与并发

- **Quart**: 异步框架，所有路由处理函数必须为 `async def`
- **Peewee DB**: 通过 `@DB.connection_context()` 装饰器管理数据库连接，请求结束时自动关闭
- **Redis 分布式锁**: `RedisDistributedLock` 保证多 Worker 间的互斥（如进度更新、缓存预热）
- **Task Executor**: 多进程模型，每个 Worker 独立拉取任务，通过 Redis 队列和数据库协调
